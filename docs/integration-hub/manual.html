1. Qué es el Centro de Integraciones

El Centro de Integraciones (módulo Integrationhub) es el punto único desde el cual el sistema se conecta con servicios externos: n8n, WhatsApp, ChatLevel.ai u otra API que se necesite. En lugar de escribir una llamada HTTP distinta en cada módulo, todo se declara aquí una sola vez y luego cualquier parte del sistema la invoca por su nombre.

Con el módulo se puede:

  • Registrar integraciones (una por servicio externo) con su URL base, tipo de ejecución, tiempo de espera y estado.
  • Declarar endpoints (una por operación: enviar mensaje, crear contacto, publicar una compra…), con su método HTTP y el tipo de cuerpo que envía.
  • Autenticarse con token, API key, contraseña, OAuth o Basic Auth, en cabecera, cuerpo o query string.
  • Mapear los campos del cuerpo/query/ruta/cabecera, tomando valores de la base de datos, de una consulta SQL de solo lectura, de un valor fijo o de los que envía el módulo que invoca la integración.
  • Programar ejecuciones con expresión cron, incluso llamando a APIs internas del propio módulo.
  • Probar una ejecución desde la interfaz y ver la petición enviada y la respuesta recibida.
  • Auditar cada llamada en el Historial, enmascarando los datos sensibles, y revisar los errores registrados.

3. Acceso, permisos y rutas

El acceso a cada función está controlado por el middleware de permisos de Spatie. Un usuario que no tenga el permiso correspondiente verá un error de acceso denegado, aunque conozca la URL.

NotaTodas las rutas del módulo viajan dentro del grupo web y exigen sesión iniciada y correo verificado (auth + verified). Las rutas de ejecución añaden además el permiso integrationhub_ejecutar. El listado completo de rutas está en el Anexo A.

4. Listado de integraciones

Pantalla de entrada del módulo (integrationhub/listado). Muestra las integraciones paginadas (10 por página) y permite buscar por nombre.

ColumnaQué muestra
NombreEl identificador de la integración tal como se usa internamente.
URL BaseEl dominio/path base sobre el que se construye cada endpoint.
TipoManual, Programada o Webhook.
EstadoActivo / Inactivo. Una integración inactiva no se ejecuta por las programaciones.
Última EjecuciónFecha de la última vez que se ejecutó algo de esa integración (o «Nunca»).

5. Crear una integración

Desde Nueva Integración (o el botón del listado) se abre el formulario de creación. Sólo hacen falta el nombre y la URL base; el resto tiene valores por defecto razonables.

CampoObligatorioDescripción y validaciones
Nombre de la IntegraciónSíTexto de hasta 100 caracteres. Es el nombre con el que se identifica el servicio (por ejemplo N8N_Global).
URL Base de la APISíDebe ser una URL válida de hasta 500 caracteres y terminar en la parte común de todos los endpoints (por ejemplo https://academy-cpa.app.n8n.cloud/webhook/). No incluyas el nombre del endpoint: cada endpoint añade su propia ruta.
DescripciónNoTexto libre para dejar constancia de para qué se usa la integración.
Tipo de EjecuciónSíManual (se dispara a mano o desde otro módulo), Programada (por cron) o Webhook (la usa el sistema cuando ocurre un evento, como la aprobación de una negociación). Es informativo: no cambia el comportamiento de la ejecución.
EstadoNoActivo por defecto. Si se desactiva, las programaciones de esa integración se saltan.
Tiempo de esperaNoEntre 5 y 300 segundos (30 por defecto). Se aplica de verdad: es el tiempo máximo que el sistema espera la respuesta de la API externa.
Intentos de reintentoNoEntre 0 y 10 (3 por defecto). Se guarda en la configuración de la integración, pero hoy no se usa al enviar: no hay reintentos automáticos.

Al guardar correctamente, el sistema redirige directamente a la pantalla de edición de la integración recién creada, donde se configuran autenticación, endpoints, mapeos y programaciones.

6. Editar una integración: las 9 pestañas

Toda la configuración vive en una sola pantalla con nueve pestañas. La primera (Datos Generales) mantiene los mismos campos de la creación; las demás se explican en las secciones siguientes.

6.1 Datos Generales

Permite cambiar nombre, URL base, descripción, tipo de ejecución, estado, tiempo de espera y reintentos. Los cambios se guardan con Guardar Cambios. Cambiar la URL base afecta a todos los endpoints de la integración, porque la URL final se arma como URL base + ruta del endpoint.

6.2 Autenticación

Define qué credenciales viajan en cada llamada. Cada registro tiene un nombre, un tipo, un valor y una ubicación.

CampoOpciones y comportamiento
Nombre del CampoNombre real de la cabecera, del parámetro o del campo del cuerpo. Por ejemplo la integración real ChatLevel.ai usa X-ACCESS-TOKEN.
UbicaciónHeader (cabecera HTTP), Body (dentro del cuerpo) o Query Param (añadido a la URL).
Tipo de CampoTexto, Password, Token, API Key, OAuth o Basic Auth. El tipo determina que el valor se enmascare en el historial.
Valor del CampoEl token o la clave. En Basic Auth se piden por separado Usuario y Contraseña y el sistema construye la cabecera Authorization: Basic … en Base64.
SeguridadLos valores de autenticación nunca se muestran completos en el historial: se reemplazan por una cadena de x de la misma longitud. Aun así, se guardan en la base de datos en texto plano, así que el acceso a la tabla integration_auth debe estar restringido.

6.3 Endpoints

Un endpoint es una operación del servicio externo. Se define con cinco datos y un interruptor de estado.

CampoDescripción
NombreIdentificador único en todo el sistema (no sólo dentro de la integración). El sistema rechaza nombres repetidos porque son la clave para ejecutar el endpoint desde otros módulos.
Ruta del EndpointParte que se añade a la URL base. Admite marcadores entre llaves, por ejemplo contacts/{contact_id}.
Método HTTPGET, POST, PUT, DELETE o PATCH.
Tipo de CuerpoJSON, XML, Form Data, Raw o Ninguno. Determina cómo se serializa el cuerpo y la cabecera Content-Type que se envía.
EstadoActivo / Inactivo. Los endpoints inactivos se omiten en las ejecuciones programadas «de todos los endpoints».
ConsejoSi un endpoint va a ser invocado desde otro módulo, ponle un nombre descriptivo y estable (por ejemplo n8n_post_negociacion). El código de los módulos llama a ese nombre literal.

6.4 Mapeo Campos

Es la pestaña más potente: define cada dato que se envía y de dónde sale. Se puede filtrar por endpoint y se puede tener un mapeo distinto por endpoint.

CampoDescripción
EndpointA qué endpoint pertenece el mapeo.
Tipo de CampoEstático, Campo de Tabla, Consulta, Calculado o Personalizado. Es descriptivo: documenta la intención del mapeo.
Tipo de OrigenEstático (valor fijo), Base de Datos (tabla y columna), Consulta SQL (sólo lectura) o Función.
Ubicación del CampoDónde viaja el dato: Parámetro URL (?key=value), Ruta URL ({campo}), Cuerpo JSON (body) o Cabecera HTTP (header).
Tabla / Campo de OrigenCuando el origen es Base de Datos, los desplegables se llenan con las tablas y columnas reales de la base de datos.
Consulta SQLCuando el origen es Consulta SQL. Se admite SELECT y WITH; se usa el primer valor de la primera fila y, si la consulta no devuelve filas, se envía el Valor por Defecto.
Valor por DefectoValor que se envía si el campo queda vacío o si la consulta no devuelve datos.
Campo ClaveEl nombre de la clave que viaja en el cuerpo o en la URL. También es la clave con la que un módulo puede sobrescribir el valor al ejecutar.
Campo ValorEl valor fijo o el marcador de variable del que se toma el dato.
ObligatoriedadRequerido u Opcional. El sistema usa esta marca para generar el ejemplo de código de la pestaña Integración y para separar los valores que el módulo debería enviar siempre.
SubitemsPara armar objetos u arreglos anidados (por ejemplo una lista de ítems): se elige la estructura Object o Array, se agregan los subcampos y, en modo Array, la consulta SQL que devuelve las filas.
Sólo consultas de lecturaEn los mapeos con origen «Consulta SQL», en los subitems y en las consultas guardadas sólo se aceptan sentencias SELECT/WITH. El sistema bloquea INSERT, UPDATE, DELETE, TRUNCATE, CREATE/ALTER/DROP, CALL, GRANT y similares, y rechaza varias sentencias en el mismo texto.
Marcadores de rutaSi un mapeo usa la ubicación «Ruta URL», la ruta del endpoint debe contener el marcador {campo}; en caso contrario el sistema rechaza el mapeo con el mensaje «La ruta del endpoint debe contener el placeholder {campo}».

6.5 Programación

Permite ejecutar automáticamente, por expresión cron, un endpoint de la integración o una API interna del módulo.

CampoDescripción
Frecuencia sugeridaAyuda para armar la expresión: cada cierta cantidad de minutos, cada hora, diario, semanal, mensual o una expresión personalizada.
Qué debe ejecutarEndpoint de esta integración o API REST del módulo Integrationhub. En el segundo caso se elige la ruta por su nombre y se envía un JSON como carga útil.
Endpoint a ejecutarUno de los endpoints de la integración. Si no se elige ninguno, la programación ejecuta todos los endpoints activos.
Expresión CronCinco campos (minuto hora día mes día-semana), por ejemplo */20 * * * * para cada 20 minutos.
EstadoActivo / Inactivo.
Cómo se ejecutanLas programaciones las procesa el comando integrationhub:run-scheduled, que el planificador ejecuta cada minuto (sin solapamiento). Cuando el destino es una API interna del módulo, la llamada se hace desde el propio servidor con host localhost, que es lo que exige el filtro de esa ruta. Detalles en la sección 9.

6.6 Ejecutar (pruebas)

Es el banco de pruebas del módulo: permite probar un endpoint real y ver exactamente qué se envió y qué respondió la API externa.

  1. Se elige el endpoint en el desplegable.
  2. Aparecen los campos del mapeo. Los marcados como requeridos se muestran como valores obligatorios y los opcionales como (Opcional). En los campos de origen «Consulta SQL» el campo se puede dejar vacío para que se ejecute la consulta configurada, o escribir un valor para forzarlo.
  3. Si hace falta, se abre Parámetros Extra y se agregan pares clave/valor en cuatro pestañas: Body, Query, Path y Headers. En Body hay un interruptor «Modo JSON» para pegar un JSON crudo (se valida antes de enviar).
  4. Se pulsa Ejecutar Ahora.

Qué devuelve una ejecución

ElementoSignificado
Ejecución exitosa / ErrorResultado general. Se considera exitoso cuando el código HTTP está entre 200 y 299.
Código de estadoEl código HTTP devuelto por la API externa.
MensajeMensaje del sistema o, si la API externa falló, el mensaje que ella devolvió (por ejemplo message o error del JSON de respuesta).
Ver datos enviadosEl detalle completo de la petición: método, URL, cabeceras, query y cuerpo, con los datos sensibles enmascarados.
Ver datos recibidosEl detalle de la respuesta: código, cabeceras y cuerpo.
«Mostrar detalle completo»Amplía o resume el JSON mostrado.
Antes de probar en producciónEl botón ejecuta la llamada de verdad contra el servicio externo. En integraciones apuntadas a producción, una prueba con datos reales crea o modifica información en el sistema de destino. Para probar sin efectos, cambia temporalmente la URL base a un servidor de pruebas o usa un endpoint cuyo único efecto sea consultar.

6.7 Integración (código)

Genera automáticamente el código PHP que otro módulo necesita para invocar ese endpoint. Se elige el endpoint y el sistema escribe el ejemplo con las claves requeridas y las opcionales, listo para copiar.

Muestra las ejecuciones registradas de la integración, de la más reciente a la más antigua, con filtros y paginación.

FiltroUso

El icono de detalle abre la ficha completa de la ejecución:

Cuánto historial se guardaPor cada integración se conservan las últimas 300 ejecuciones que no tienen lote; las más antiguas se van descartando automáticamente. Las ejecuciones con batch_id (lotes de procesos masivos) no entran en esa limpieza.

6.9 Errores

Muestra los errores registrados por el módulo; se puede buscar por texto, filtrar por fechas, ver el detalle y borrar. Cada error trae su origen, que normalmente es la clase que lo provocó (por ejemplo el job ProcessWhatsappFlow).

Errores del historial vs. errores de esta pestañaEl Historial registra todas las ejecuciones, exitosas o no, con todo el detalle técnico. Esta pestaña registra excepciones de los procesos de integración (por ejemplo, si un job de WhatsApp falla al llamar a un endpoint), con el mensaje y el origen del fallo.

7. Páginas globales: Errores de Integración y Plantillas / Flujos

7.1 Errores de Integración

Es la vista transversal de errores de todas las integraciones (integrationhub/errores). Tiene buscador, rango de fechas, botón «Limpiar filtros» y, por registro, el detalle y la opción de eliminar; además permite vaciar el registro completo.

7.2 Plantillas / Flujos

8. Ejecutar integraciones desde otros módulos

La forma recomendada de usar una integración desde el código es runEndpoint(). Sólo hay que pasar el nombre del endpoint y los valores; el módulo se encarga de la URL, la autenticación, los mapeos y el registro en el historial.

use Modules\Integrationhub\Http\Controllers\IntegrationhubController;

// Ejecución simple: se envían sólo los valores que el endpoint necesita
$respuesta = app(IntegrationhubController::class)->runEndpoint('create_contact', [
    'phone'      => '51987654321',
    'email'      => 'persona@correo.com',
    'first_name' => 'Nombre Apellido',
]);

// Respuesta JSON: message, status_code, request, received, response, executed_at
if ($respuesta->getData(true)['status_code'] === 200) {
    // la API externa aceptó la llamada
}
ParámetroPara qué sirve
$endpointNombre exacto del endpoint (único en todo el sistema).
$fieldValuesValores que sobrescriben los mapeos del endpoint, indexados por Campo Clave. Si no se envía un valor, se usa lo configurado en el mapeo (valor fijo, tabla o consulta).
$extraParamsDatos adicionales fuera del mapeo, en path, query, body y headers. Es la vía que usa, por ejemplo, el módulo Commercial para publicar el JSON completo de una negociación en el body.
$trackResultsSi es true (por defecto), la ejecución se guarda en el Historial. Con false la llamada se hace igual, pero no deja registro.
$batchIdIdentificador de lote para agrupar varias ejecuciones y poder verlas juntas en el Historial (y para que la limpieza automática no las borre).

Errores típicos al invocar por nombre

CódigoCuándo ocurre
404No existe ningún endpoint con ese nombre en ninguna integración. Ocurre, por ejemplo, cuando el endpoint se creó sólo en producción y no en el entorno local.
422El nombre del endpoint está duplicado en varias integraciones; hay que dejar un único endpoint con ese nombre.

Ejecución por HTTP

Además de la vía interna, el módulo expone dos rutas POST protegidas con sesión y permiso de ejecución, útiles para pruebas o para herramientas externas que ya tengan sesión del sistema:

RutaCuerpo de la petición
POST /integrationhub/execute-by-endpoint/{endpoint}field_values, extra_params, track_results, batch_id. Se resuelve por nombre de endpoint.
POST /integrationhub/execute-by-name/{integration}/{endpoint}Igual, pero además hay que indicar a qué integración pertenece el endpoint.
POST /integrationhub/execute/{id}Igual, pero indicando el identificador de la integración y el endpoint_id.

9. Operación y mantenimiento

9.1 Procesos automáticos

ComandoFrecuenciaQué hace
integrationhub:run-scheduledCada minuto (sin solapamiento)Ejecuta las programaciones activas cuya hora ya venció: el endpoint elegido, todos los endpoints activos de la integración, o la API interna configurada. Actualiza la última y la próxima ejecución.
integrationhub:carrito-abandonadoCada minutoBusca carritos sin pagar de más de 10 minutos y encola el envío por WhatsApp (máximo 5 avisos por carrito).
integrationhub:birthday-whatsapp-sendDiario a las 09:09 (hora de Lima)Busca a quienes cumplen años hoy y encola el saludo por WhatsApp usando el flow id de Plantillas / Flujos.
RequisitoLos dos comandos de negocio encolan trabajos (jobs) que necesitan un worker de colas en ejecución (queue:work). Si el worker no está activo, las llamadas a la integración no se realizan.

9.2 Seguridad de los datos

  • Enmascarado en el historial: al guardar una ejecución, los valores cuyo nombre sea password, token, api_key, secret, authorization, credential, bearer, private_key (o los de la autenticación de la integración) se reemplazan por x. Lo mismo se aplica a los parámetros sensibles de la URL.
  • Sólo lectura en SQL: todas las consultas configurables pasan por el validador que rechaza sentencias de escritura y múltiples sentencias.
  • Verificación TLS desactivada: las llamadas salientes se hacen sin validar el certificado del servidor externo. Es cómodo en pruebas, pero conviene activarlo si el servicio de destino lo soporta.
  • Credenciales en texto plano: los tokens y contraseñas se guardan tal cual en la base de datos; el cuidado debe estar en los permisos de la base y del módulo.

9.3 Comportamientos que conviene conocer

ComportamientoDetalle
ReintentosEl campo «Intentos de reintento» se guarda en la configuración pero no se aplica hoy: si la llamada falla, no se reintenta automáticamente.
Tiempo de esperaSí se aplica (valor de la integración; 30 s por defecto). Un tiempo excedido se registra como error con código 500.
Limpieza del historialSe conservan las últimas 300 ejecuciones por integración sin lote. Los lotes se conservan siempre.
Cuerpo tipo RawSe envía el primer valor del cuerpo; si es un arreglo, se convierte a JSON.
Cuerpo tipo XMLEl cuerpo se convierte automáticamente de arreglo a XML.
Pestaña de consultas guardadasLa tabla de consultas (integration_queries) y su pantalla existen en el código pero no están enlazadas a ninguna pestaña de la interfaz: hoy las consultas se definen directamente en los mapeos de campos.
Cambiar el nombre de un endpointRompe las llamadas que lo invocan por nombre desde otros módulos. Si hay que renombrarlo, hay que actualizar el código que lo llama.

10. Solución de problemas

SíntomaCausa y solución
«No existe el endpoint 'X' en ninguna integración»El nombre no coincide con ningún endpoint (suele ser un endpoint que existe en producción pero no en el entorno donde se ejecuta). Verifica el nombre en la pestaña Endpoints y que la integración sea la correcta.
«El endpoint 'X' está duplicado en varias integraciones»Hay dos endpoints con el mismo nombre. Renombra uno para poder ejecutar por nombre.
«Ya existe un endpoint con ese nombre»El nombre debe ser único en todo el sistema, no sólo dentro de la integración.
«La ruta del endpoint debe contener el placeholder {campo}»El mapeo usa la ubicación «Ruta URL» pero la ruta no tiene ese marcador. Añádelo a la ruta del endpoint.
«Solo se permiten consultas SELECT…»La consulta del mapeo, del subitem o de la consulta guardada contiene una sentencia de escritura o varias sentencias. Deja una única consulta de lectura.
La ejecución queda en error con código 500 y mensaje de timeoutLa API externa no respondió dentro del tiempo configurado. Sube el «Tiempo de espera» de la integración (máximo 300 s) o revisa el servicio externo.
Error 404 del webhook de n8nLa ruta del webhook cambió en n8n. Copia la nueva URL del webhook en la pestaña Endpoints.
La ejecución funciona pero no aparece en el HistorialSe ejecutó con track_results = false (desde código o desde una API). Actívalo para que quede registrada.
Un dato llega vacío a la API externaRevisa el mapeo: si el origen es «Base de Datos» o «Consulta SQL» y no hay datos, se envía el Valor por Defecto; si tampoco lo hay, llega vacío.
La programación no se ejecutaComprueba que la programación esté activa, que la integración esté activa, que el planificador del sistema esté corriendo (schedule:run cada minuto) y que el worker de colas esté levantado.

D. Anexo D — Checklist: agregar una integración nueva

  1. Crear la integración en Nueva Integración: nombre, URL base, tipo de ejecución y estado.
  2. Configurar la autenticación en la pestaña Autenticación: nombre del campo (tal como lo espera la API externa), tipo, valor y ubicación.
  3. Crear el endpoint en Endpoints: nombre único y descriptivo, ruta, método y tipo de cuerpo.
  4. Mapear los campos en Mapeo Campos: para cada dato que se envía, definir ubicación, origen, valor por defecto y obligatoriedad. Si el dato depende de un identificador que envía el módulo llamador, márcalo como requerido y usa su Campo Clave para recibirlo.
  5. Probar en la pestaña Ejecutar, primero con datos de prueba; revisar el código de estado, los datos enviados y los recibidos.
  6. Revisar el Historial para confirmar que la ejecución quedó registrada, que el request se ve correcto y que no hay datos sensibles expuestos.
  7. Programar (si corresponde) en Programación, verificando la próxima ejecución calculada.
  8. Integrar desde el módulo que la va a usar: copiar el ejemplo de la pestaña Integración y comprobar que la llamada se hace con el nombre exacto del endpoint.
  9. Documentar para qué sirve ese endpoint y qué módulos lo invocan.

E. Anexo E — Caso real: N8N_Global y el webhook de negociaciones

Es la integración más usada del sistema y sirve como ejemplo completo de todo lo explicado.

ElementoValor real
IntegraciónN8N_Global, tipo Webhook, activa
URL basehttps://academy-cpa.app.n8n.cloud/webhook/
Endpointsn8n_post_negociacion (publica la negociación aprobada) y n8n_post_compra (publica una compra del Online Shop)
Quién la invocaEl módulo Commercial al verificar/aprobar una negociación y el módulo Onlineshop al completar una compra
Cómo se envía el contenidoEl módulo que la usa arma el JSON y lo pasa como extra_params.body; los mapeos de campos del endpoint completan el resto

El cuerpo que recibe n8n incluye, entre otras claves, evento, fecha, origen, negociacion, persona, usuario, estudiante, comprobante e items. Los valores se toman de la negociación y, cuando un dato no se declaró en el formulario, se completan desde la ficha de la persona: es la regla «la negociación manda, la ficha rellena».

// Forma de invocación real (módulo Commercial)
app(IntegrationhubController::class)->runEndpoint(
    'n8n_post_negociacion',
    [],                                  // los valores no vienen del mapeo…
    ['body' => $payload],                // …sino del JSON que arma el módulo
    true                                 // y la ejecución queda en el Historial
);
Comprobar el resultadoCada envío queda en el Historial de N8N_Global con su código HTTP y su tiempo. Si n8n responde 200 pero el flujo no se ejecuta, el problema suele estar en el flujo de n8n y no en el sistema: el request y la respuesta exactos están en el detalle de la ejecución.
